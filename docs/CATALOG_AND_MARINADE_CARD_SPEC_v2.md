# SPICELAND — CATALOG PAGE & MARINADE CARD SPECIFICATION

> Технічна специфікація сторінки каталогу, фільтрів, паралакс-сцен і універсальної картки маринаду.  
> Мова інтерфейсу: **українська**.  
> Стилі: **SCSS**. Методологія: **BEM**. Архітектура: компонентна.

---

# 1. Призначення

Документ описує:

1. Каталог рідких, сухих і змішаних маринадів.
2. Адаптивну сітку карток.
3. Ліву навігаційну панель.
4. Комбінований фільтр.
5. Правила зміни паралакс-фону.
6. Закритий і розгорнутий стани картки.
7. Анімацію круга маринаду, що перетворюється на краплю.
8. Галерею готових страв і повноекранний перегляд.
9. Архітектуру HTML, SCSS і JavaScript.
10. Додавання товарів у кошик.
11. Універсальний компонент картки, який створюється з даних без копіювання розмітки.

---

# 2. Режими каталогу

Після кінематографічного переходу користувач потрапляє в один із режимів:

- каталог рідких маринадів;
- каталог сухих маринадів;
- змішаний каталог рідких і сухих маринадів.

Кожен режим має власний паралакс-фон. Основний контент: ліва панель, сітка карток, навігація між групами товарів, фільтр і lightbox.

---

# 3. Кількість карток

## Desktop — 1024 px і більше

- 6 карток;
- 3 картки в ряд;
- 2 ряди;
- стрілки вліво/вправо для наступної групи карток.

```text
[Картка] [Картка] [Картка]
[Картка] [Картка] [Картка]
```

## Tablet / Laptop — 768–1023 px

- 4 картки;
- 2 картки в ряд;
- 2 ряди;
- стрілки та/або свайп.

```text
[Картка] [Картка]
[Картка] [Картка]
```

## Mobile — менше 768 px

- одна основна картка займає приблизно 70% ширини;
- по 15% сусідніх карток видно ліворуч і праворуч;
- горизонтальний свайп;
- інерція;
- snap до найближчої картки.

---

# 4. Ліва панель каталогу

На desktop і tablet панель знаходиться ліворуч. На mobile відкривається як окремий drawer і блокує прокрутку сторінки.

## 4.1. Головна

Кнопка **«Головна»** повертає на головну сторінку плавним переходом.

## 4.2. Протилежна категорія

Якщо відкриті рідкі:

```text
Каталог сухих маринадів
```

Якщо відкриті сухі:

```text
Каталог рідких маринадів
```

Перехід виконується кінематографічно, без різкої зміни сцени.

---

# 5. Фільтр

## 5.1. Структура

```text
Фільтр

Тип маринаду
Колір
Для чого

[Застосувати]
[Скинути фільтр]
```

## 5.2. Тип маринаду

Можна вибрати:

- Рідкі;
- Сухі;
- Рідкі + Сухі.

## 5.3. Колір

Можна вибрати один або кілька кольорів:

- Зелені;
- Червоні;
- Жовті.

## 5.4. Для чого

Візуальні кнопки або чекбокси з іконками:

- Птиця;
- М’ясо;
- Риба.

Можна вибрати один або кілька варіантів.

## 5.5. Комбінації

Фільтр підтримує довільні комбінації.

Приклади:

```text
Рідкі + Зелені + Птиця
```

Показати тільки зелені рідкі маринади для птиці.

```text
Рідкі + Сухі + Птиця
```

Показати всі рідкі та сухі маринади для птиці.

```text
Сухі + Червоні + М’ясо
```

Показати тільки червоні сухі маринади для м’яса.

## 5.6. «Застосувати»

Фільтр застосовується тільки після натискання кнопки.

Після натискання:

1. Обрані параметри застосовуються.
2. Поточні картки трохи зменшуються.
3. Плавно зникають.
4. Нові картки плавно з’являються.
5. Усі розкриті групи фільтра згортаються.
6. Обрані значення залишаються активними.

## 5.7. «Скинути фільтр»

Після натискання:

1. Усі параметри очищаються.
2. Показуються всі картки поточного режиму.
3. Чекбокси й активні іконки скидаються.
4. Усі групи фільтра згортаються.
5. Панель повертається у початковий вигляд.

---

# 6. Зміна паралакс-фону

## 6.1. Тільки рідкі маринади

Фон рідких залишається незалежно від кольору та призначення.

Три шари:

- дальній — озеро, гори, зелений ліс;
- середній — альтанка;
- передній — світлий стіл, мангал, готова страва.

Додатково:

- легкі відблиски на воді;
- листя злегка коливається.

## 6.2. Тільки сухі маринади

Фон перемикається на сухий.

Три шари:

- дальній — зелений ліс;
- середній — зона барбекю та мангал;
- передній — світлий стіл і готовий шашлик.

Додатково:

- дим постійно й природно коливається;
- листя рухається дуже легко.

## 6.3. Рідкі + сухі

Використовується третій окремий паралакс-фон для змішаного режиму. Його дизайн буде затверджено пізніше.

## 6.4. Коли змінюється фон

Фон змінюється тільки після натискання **«Застосувати»**.

Порядок:

1. Картки починають анімацію фільтрації.
2. Старий фон плавно зникає.
3. Новий фон проявляється.
4. Новий паралакс запускається після завершення переходу.

---

# 7. Загальний стиль карток

Картки мають бути максимально прозорими, щоб паралакс залишався видимим.

Рекомендовано:

```scss
background: rgba(255, 255, 255, 0.04);
border: 1px solid rgba(255, 255, 255, 0.22);
backdrop-filter: blur(4px);
-webkit-backdrop-filter: blur(4px);
```

Не використовувати:

- суцільний чорний фон;
- важкі темні підкладки;
- великі непрозорі блоки.

Картки повинні бути компактними та мати помірні проміжки між собою.

---

# 8. Закритий стан картки

## 8.1. Ліва частина

1. Назва маринаду.
2. Тип: рідкий або сухий.
3. П’ять коротких смакових характеристик.
4. Кнопка **«Докладніше»**.

Приклад смаків:

```text
Гострий
Солодкий
Пряний
Копчений
Часниковий
```

Фінальні значення передаються через дані товару.

## 8.2. Права частина

- невеликий круг із реальною текстурою або фотографією маринаду;
- круг не повинен бути великим;
- це головний інтерактивний візуальний об’єкт картки.

---

# 9. Відкриття картки

Користувач натискає **«Докладніше»**.

Круг маринаду:

1. Плавно деформується.
2. Перетворюється на краплю.
3. Витягується вниз.
4. Стікає.
5. Після завершення стекання під краплею відкривається галерея готових страв.

Ключові правила:

- страва не видима до завершення анімації;
- галерея не відкривається збоку;
- вона з’являється саме під краплею;
- ефект має виглядати так, ніби маринад капає на блюдо.

Порядок появи:

1. Крапля завершує рух.
2. Галерея проявляється зверху вниз.
3. Після галереї з’являється детальний опис.
4. Кнопка змінюється на **«Згорнути»**.
5. З’являється хрестик закриття.

---

# 10. Галерея страв

Для одного маринаду:

- 3–4 фотографії готових страв.

Навігація desktop:

- стрілки вліво/вправо;
- клік по прев’ю;
- за потреби колесо миші.

Навігація mobile:

- горизонтальний свайп;
- інерція;
- snap.

Галерея знаходиться:

- під краплею;
- усередині тієї самої картки;
- не збоку;
- не в окремій колонці.

---

# 11. Збільшення фотографій

## Desktop

При наведенні:

- з’являється іконка лупи;
- курсор — `zoom-in`;
- фото отримує легкий акцент.

Після кліку:

- відкривається повноекранний lightbox;
- фон затемнюється;
- прокрутка блокується;
- фото можна перегортати;
- є стрілки;
- є хрестик;
- `Escape` закриває lightbox.

## Mobile

- tap відкриває lightbox;
- swipe перегортає фото;
- pinch-to-zoom допускається, якщо не погіршує стабільність.

---

# 12. Нижня інформаційна панель

Після галереї на всю ширину картки з’являється інформаційна зона.

Вона містить:

## 12.1. Короткий опис

Наприклад:

```text
Червоний маринад має виразний пряно-солодкий смак із легкою гостротою.
Найкраще підходить для курятини та свинини.
```

## 12.2. Для чого підходить

- птиця;
- м’ясо;
- риба.

## 12.3. Склад

```text
Склад: ...
```

## 12.4. Вага упаковки

Рідкий маринад — орієнтовно `2,5 кг`.

Сухий маринад — орієнтовно `1 кг`.

Вага є даними товару, а не жорстко прописаним значенням.

## 12.5. Ціна

```text
Ціна: ...
```

Ціна передається через дані картки.

# 13. Додавання у кошик

## 13.1. Розташування кнопки

У закритій картці під кнопкою «Докладніше» розташована кнопка:

```text
Додати у кошик
```

У розгорнутій картці ця кнопка також залишається доступною. Вона може залишатися у верхній частині картки або дублюватися біля ціни, але основним джерелом дії залишається одна й та сама функція компонента.

## 13.2. Дані, що передаються у кошик

Після натискання до кошика передаються:

- `id` маринаду;
- назва маринаду;
- тип: рідкий або сухий;
- вага конкретного пакування;
- ціна конкретного пакування;
- кількість;
- мініатюра товару, якщо вона потрібна для відображення у кошику.

Приклад:

```js
{
  productId: "red-liquid-01",
  name: "Червоний маринад",
  type: "liquid",
  packageWeight: "2.3 kg",
  unitPrice: 320,
  quantity: 1,
  thumbnail: "assets/images/marinades/red-liquid-texture.webp"
}
```

Якщо вага товару в картці дорівнює `2,3 кг`, у кошику повинно відображатися:

```text
Червоний маринад
Вага: 2,3 кг
Кількість: 1
```

Якщо сухий маринад має вагу `1 кг`, у кошик передається саме `1 кг`.

## 13.3. Кількість товару

При повторному додаванні того самого товару з тим самим пакуванням:

- не створювати хаотичні дублікати;
- збільшувати `quantity`;
- підсумок розраховувати як `unitPrice × quantity`.

Якщо в майбутньому один маринад матиме кілька варіантів ваги, кожна вага вважається окремою позицією кошика.

## 13.4. Майбутній загальний підсумок

Сам кошик розробляється окремим компонентом на наступному етапі.

Каталог уже зараз повинен бути підготовлений до передачі даних для:

- списку позицій;
- кількості кожної позиції;
- ваги пакування;
- ціни за одиницю;
- проміжної суми позиції;
- загального підсумку кошика.

## 13.5. Стан кнопки

Після успішного додавання:

- текст може коротко змінитися на «Додано»;
- можна показати невелику іконку підтвердження;
- через короткий час кнопка повертається до «Додати у кошик»;
- не використовувати різкі спалахи або важкі анімації.

## 13.6. Доступність

- кнопка є справжнім `<button type="button">`;
- має зрозумілий `aria-label`;
- доступна з клавіатури;
- повідомлення про додавання оголошується через `aria-live="polite"`.

---

# 14. Закриття картки

Способи:

1. Кнопка **«Згорнути»**.
2. Хрестик.
3. Відкриття іншої картки.
4. Клік поза карткою — лише якщо не шкодить UX.

Анімація закриття:

1. Інформаційна панель зникає.
2. Галерея згортається.
3. Крапля піднімається назад.
4. Крапля повертається у круг.
5. Кнопка знову стає **«Докладніше»**.

Одночасно може бути відкрита тільки одна картка. Якщо відкривається інша, попередня автоматично закривається.

# 15. Компонентність карток

## 15.1. Одна універсальна картка

Не створювати окрему HTML-розмітку вручну для кожного маринаду.

Повинен існувати один універсальний компонент:

```text
MarinadeCard
```

Він отримує дані конкретного продукту і автоматично формує:

- назву;
- тип;
- п’ять смакових характеристик;
- текстуру маринаду;
- фотографії страв;
- опис;
- призначення;
- склад;
- вагу;
- ціну;
- кнопку «Докладніше / Згорнути»;
- кнопку «Додати у кошик».

## 15.2. Додавання нового товару

Щоб додати новий маринад, розробник повинен:

1. Додати новий об’єкт у файл даних.
2. Вказати тексти та шляхи до зображень.
3. Не копіювати HTML.
4. Не створювати новий JavaScript-модуль.
5. Не дублювати SCSS.

Приклад використання:

```js
marinades.forEach((marinade) => {
  catalog.append(createMarinadeCard(marinade));
});
```

## 15.3. Незалежність компонента

Кожна відрендерена картка:

- має власний унікальний `id`;
- керує своїм станом через єдиний контролер;
- не містить жорстко прописаних даних;
- може бути видалена або додана без змін в інших картках;
- підтримує всі типи та кольори через модифікатори або data-атрибути.

## 15.4. Джерело даних

Рекомендований файл:

```text
src/data/marinades.js
```

або:

```text
src/data/marinades.json
```

Дані є єдиним джерелом правди для каталогу, фільтра та кошика.

## 15.5. Автоматична інтеграція

Після додавання нового об’єкта товар автоматично:

- з’являється у відповідному каталозі;
- бере участь у фільтрації;
- отримує правильний фон за типом;
- відкриває галерею;
- додається у кошик;
- відображається на потрібній сторінці пагінації.

# 21. Адаптивність картки

## Desktop

- текст ліворуч;
- круг маринаду праворуч;
- галерея під краплею;
- опис на всю ширину картки.

## Tablet

- та сама логіка;
- менші відступи;
- компактніша типографіка;
- менше видимих прев’ю.

## Mobile

- назва і смаки зверху;
- круг нижче або праворуч залежно від ширини;
- кнопка на всю ширину;
- горизонтальна галерея;
- опис вертикально;
- lightbox на весь екран.

---

# 22. Доступність

- усі дії — через справжні `<button>`;
- усі фото мають `alt`;
- lightbox має `aria-modal="true"`;
- картку можна відкрити клавіатурою;
- `Escape` закриває lightbox і картку;
- видимий `focus-visible`;
- не покладатися лише на колір.

---

# 23. Продуктивність

- WebP / AVIF;
- lazy loading для галереї;
- preload тільки першого видимого контенту;
- GPU-friendly анімації;
- `transform` і `opacity`;
- не анімувати `width`, `height`, `top`, `left` без потреби;
- `requestAnimationFrame`;
- для краплі дозволено GSAP;
- підтримати `prefers-reduced-motion`.
